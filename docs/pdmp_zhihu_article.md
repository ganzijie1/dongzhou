# PDMP 是什么？一种比 MDP 更连续、比 SDE 更“事件驱动”的随机过程

假设你正在模拟一场 5v5 游戏。

英雄的位置在连续变化，技能冷却一秒一秒减少，持续伤害不断结算；与此同时，技能可能命中或落空，英雄可能死亡，野怪会刷新，传送可能完成或被打断。

如果把每一帧都离散成 MDP，状态空间会迅速膨胀；如果直接使用随机微分方程，又会给连续轨迹加入大量并不存在的 Brownian 噪声。

这正是 **PDMP（Piecewise-Deterministic Markov Process，分段确定性马尔可夫过程）** 擅长的地方：

> 系统在大部分时间里按照确定性规律连续运动，只在随机事件发生时瞬间跳变。

PDMP 介于 ODE、连续时间 Markov 链和随机混合系统之间。它既保留连续时间动力学，又能自然处理故障、击杀、放电、到达、刷新等离散事件。

---

## 一、先用一句话理解 PDMP

一个 PDMP 可以想成下面的循环：

1. 从当前状态出发，沿一条确定性轨迹运动；
2. 根据当前状态决定“事件有多容易发生”；
3. 事件发生后，状态瞬间跳到另一个位置；
4. 从新状态继续运动。

因此，一个基本 PDMP 由三部分决定：

$$\left(\phi,\lambda,Q\right)$$

- $\phi$：确定性流，决定两次事件之间如何运动；
- $\lambda$：跳跃强度，决定事件何时发生；
- $Q$：跳跃核，决定事件发生后跳到哪里。

如果系统还有“到达边界就必须触发”的事件，则还要加入边界规则。

---

## 二、第一部分：确定性流

在两次跳跃之间，状态满足常微分方程：

$$\frac{dX_t}{dt}=F(X_t)$$

从状态 $x$ 出发，经过时间 $s$ 后的位置记为：

$$X_{t+s}=\phi_s(x)$$

它必须满足流的半群性质：

$$\phi_0(x)=x,\qquad \phi_{t+s}(x)=\phi_t(\phi_s(x))$$

例如：

- 设备温度按热力学方程上升；
- 排队系统的工作量按服务速度下降；
- 英雄按照当前速度移动；
- 技能冷却以固定速度归零；
- 持续伤害按照预设曲线结算。

这里的关键词是“确定性”：给定当前完整状态，在下一次随机事件之前，轨迹已经确定。

---

## 三、第二部分：跳跃强度

跳跃强度写作：

$$\lambda(x)\geq0$$

当系统处于状态 $x$ 时，在一个很短的时间 $\Delta t$ 内发生事件的概率近似为：

$$\mathbb P(\text{发生跳跃}\mid X_t=x)=\lambda(x)\Delta t+o(\Delta t)$$

因此 $\lambda(x)$ 越大，事件越容易马上发生。

从状态 $x$ 出发，沿流运动时，下一次随机跳跃晚于 $t$ 的概率为：

$$\mathbb P_x(T_1>t)=\exp\left[-\int_0^t\lambda(\phi_s(x))\,ds\right]$$

定义累计风险：

$$\Lambda_x(t)=\int_0^t\lambda(\phi_s(x))\,ds$$

那么：

$$\mathbb P_x(T_1>t)=e^{-\Lambda_x(t)}$$

这条公式非常重要。它说明等待时间一般不是简单的指数分布，因为系统在等待期间仍然运动，强度也在变化。

只有当 $\lambda$ 为常数时，等待时间才退化为普通指数分布。

---

## 四、第三部分：跳跃核

事件发生前的状态记为 $X_{T_1^-}$，事件后的状态根据概率核 $Q$ 采样：

$$X_{T_1}\sim Q(\cdot\mid X_{T_1^-})$$

例如设备故障后，可能以不同概率进入“可维修故障”或“彻底损坏”；技能命中后，目标可能进入减速、眩晕或免疫状态。

如果有多种事件，可以分别定义强度：

$$\lambda(x)=\sum_{k=1}^K\lambda_k(x)$$

在事件已经发生的条件下，它属于第 $k$ 类的概率为：

$$\mathbb P(K=k\mid X_{T^-}=x)=\frac{\lambda_k(x)}{\lambda(x)}$$

第 $k$ 类事件再使用自己的跳跃核 $Q_k$。

如果某类事件的结果完全确定，也可以使用重置映射：

$$X_T=R_k(X_{T^-})$$

例如英雄死亡后立即进入死亡模式，冷却归零后技能立即切换为可用状态。

---

## 五、随机事件和边界事件不是一回事

PDMP 中经常同时存在两类事件。

第一类是随机事件，例如设备何时故障、一次攻击是否暴击、一个数据包何时到达。

第二类是边界事件。例如：

- 技能冷却精确归零；
- 复活倒计时结束；
- 资源库存耗尽；
- 角色到达传送终点；
- 温度达到强制关机阈值。

沿流首次到达边界的时间为：

$$t^{\star}(x)=\inf\{t>0:\phi_t(x)\in\partial E\}$$

真实的下一事件时间是：

$$T_1=\min\{T_{\lambda},t^{\star}(x)\}$$

一个常见错误，是把确定倒计时也拟合成指数等待时间。这样会让本来确定的刷新、复活或冷却事件出现不必要的随机误差。

## 六、PDMP 和其他模型到底有什么区别？

| 模型 | 跳跃之间如何变化 | 是否有随机跳跃 | 是否有连续扩散噪声 |
| --- | --- | --- | --- |
| ODE | 确定性连续变化 | 否 | 否 |
| CTMC | 通常保持不变 | 是 | 否 |
| SDE | 随机连续变化 | 通常没有 | 是 |
| PDMP | 确定性连续变化 | 是 | 通常没有 |
| Jump Diffusion | 随机连续变化 | 是 | 是 |

连续时间 Markov 链其实是 PDMP 的特殊情形，只需令：

$$F(x)=0$$

此时系统在跳跃之间完全不动。

ODE 也是特殊情形，只需令：

$$\lambda(x)=0$$

如果连续轨迹满足：

$$dX_t=b(X_t)dt+\sigma(X_t)dW_t$$

那么连续部分已经含有 Brownian 噪声，应使用 SDE、jump diffusion 或 switching diffusion，而不是纯 PDMP。

## 七、PDMP 的生成元为什么重要？

对足够光滑的函数 $f$，PDMP 的无穷小生成元为：

$$\mathcal Lf(x)=\nabla f(x)^{\mathsf T}F(x)+\lambda(x)\int\left[f(y)-f(x)\right]Q(x,dy)$$

它包含两个部分：

$$\text{生成元}=\text{连续输运}+\text{随机跳跃}$$

第一项描述状态沿 ODE 移动时，函数值如何变化；第二项描述随机事件带来的平均变化。

生成元把 PDMP 的大部分理论连接在一起：

- Dynkin 公式；
- Kolmogorov 前向和后向方程；
- 鞅和参数估计；
- 稳定性分析；
- 最优控制与 HJB。

例如 Dynkin 公式为：

$$\mathbb E_x[f(X_t)]=f(x)+\mathbb E_x\left[\int_0^t\mathcal Lf(X_s)\,ds\right]$$

因此：

$$f(X_t)-f(X_0)-\int_0^t\mathcal Lf(X_s)\,ds$$

在适当条件下是一个鞅。

## 八、怎么精确模拟一个 PDMP？

最自然的方法不是设置一个很小的固定时间步，而是直接寻找下一事件。

先采样：

$$E\sim\operatorname{Exp}(1)$$

然后沿确定性流求解：

$$\int_0^{\tau}\lambda(\phi_s(x))\,ds=E$$

如果 $\tau<t^{\star}(x)$，就在 $\tau$ 发生随机跳跃；否则先触发边界事件。

完整流程是：

1. 从当前状态开始积分 ODE；
2. 同时积分累计风险；
3. 累计风险达到随机阈值 $E$ 时停止；
4. 确定事件类型；
5. 根据跳跃核采样新状态；
6. 从新状态重复。

如果累计风险无法方便求逆，可以使用 thinning：先用一个更大的强度生成候选事件，再按真实强度与上界强度之比接受。

### 一个简单的设备老化示例

假设设备损耗 $x$ 以速度 $v$ 增长：

$$\dot x=v$$

故障强度随损耗线性增加：

$$\lambda(x)=\lambda_0+\alpha x$$

从 $x_0$ 出发，累计风险为：

$$\Lambda(t)=(\lambda_0+\alpha x_0)t+\frac12\alpha vt^2$$

因此可以直接求解 $\Lambda(\tau)=E$，得到下一次故障时间。

~~~python
import math
import random


def next_failure_time(x0, speed, lambda0, alpha):
    threshold = -math.log(random.random())
    a = 0.5 * alpha * speed
    b = lambda0 + alpha * x0

    if abs(a) < 1e-12:
        return threshold / b

    return (-b + math.sqrt(b * b + 4.0 * a * threshold)) / (2.0 * a)


def simulate_failures(horizon, speed=0.02, lambda0=0.01, alpha=0.08):
    t = 0.0
    damage = 0.0
    failures = []

    while t < horizon:
        wait = next_failure_time(damage, speed, lambda0, alpha)
        if t + wait > horizon:
            break

        damage += speed * wait
        t += wait
        failures.append((t, damage))

        # 维修后的确定性重置
        damage = 0.0

    return failures
~~~

这个模拟器没有用微小时间步反复检查“是否故障”，而是直接生成下一次事件时间。

## 九、受控 PDMP：动作可以改变什么？

如果决策者能够影响连续动力学、事件概率或事件结果，就得到受控 PDMP：

$$\dot X_t=F(X_t,A_t)$$

$$\lambda=\lambda(X_t,A_t)$$

$$Q=Q(\cdot\mid X_t,A_t)$$

动作可能改变：

- 移动方向和资源消耗速度；
- 故障、命中或暴露事件的发生强度；
- 事件发生后的伤害和控制结果；
- 连续运行成本和离散事件成本。

一个无限时域折扣成本模型可以写成：

$$V(x)=\inf_{\pi}\mathbb E_x^{\pi}\left[\int_0^{\infty}e^{-\beta t}c(X_t,A_t)\,dt+\sum_n e^{-\beta T_n}k(X_{T_n^-},X_{T_n})\right]$$

它的形式 HJB 方程为：

$$\beta V(x)=\inf_a\left\{c(x,a)+\nabla V(x)^{\mathsf T}F(x,a)+\lambda(x,a)\int[V(y)-V(x)]Q(dy\mid x,a)\right\}$$

与普通连续控制相比，多了一个非局部跳跃积分项。

如果决策者还能主动触发维修、回城、撤退、传送或状态重置，就会进一步形成脉冲控制和拟变分不等式 QVI。

## 十、为什么 PDMP 特别适合 5v5 游戏？

可以把游戏状态写成：

$$X_t=(M_t,Z_t)$$

其中 $M_t$ 是离散模式，例如：

- 存活或死亡；
- 移动、施法、控制或回城；
- 技能的不同阶段；
- 大型目标的未刷新、存活或被击杀状态。

$Z_t$ 是连续状态，例如：

- 位置和朝向；
- 血量、法力和护盾；
- 技能冷却；
- 持续伤害剩余量；
- 移速、攻击前摇和资源。

### 两次事件之间

位置、冷却、回复和持续效果按照确定性或近似确定性流演化：

$$\dot Z_t=F(M_t,Z_t,A_t)$$

### 随机事件

命中、暴击、被发现、打断和敌方出现可以用状态相关强度描述：

$$\lambda_k(x,a)=\lambda_k^0(x)\exp\{\theta_k^{\mathsf T}\psi(x,a)\}$$

### 确定事件

复活完成、冷却归零、目标固定时间刷新，应作为边界事件。

### 跳跃

击杀会让角色从存活模式跳到死亡模式；升级会重置属性；技能命中会改变血量和控制状态；目标被击杀会改变地图资源。

这样建模后，系统不用每帧都解决一个庞大的离散 MDP，而可以在事件之间执行连续控制，在事件时刻更新高层决策。

## 十一、部分可观测 PDMP

真实状态并不总能直接看到。例如战争迷雾下，敌人的位置、回城状态和技能冷却可能未知。

此时应维护信念：

$$b_t(dx)=\mathbb P(X_t\in dx\mid\mathcal Y_t)$$

有趣的是，“长时间没有发生事件”本身也是信息。

如果某些隐藏状态具有很高的事件强度，却一直没有观察到事件，那么这些状态的后验概率应该下降。未发生事件的存活因子为：

$$\exp\left[-\int_0^t\lambda(\phi_s(x))\,ds\right]$$

因此 PDMP 过滤不仅要在观察出现时做 Bayes 更新，也要在没有事件的区间持续更新。

## 十二、建模时最容易犯的错误

### 1. 状态不完整

如果事件概率取决于上次事件过去多久，就必须把“年龄”放进状态：

$$A_t=t-T_{N_t}$$

遗漏冷却、阶段或累计量后，模型可能不再具有 Markov 性。

### 2. 把确定倒计时当成随机事件

复活 30 秒后结束就是边界事件，不应使用指数分布近似。

### 3. 用固定小步长代替事件定位

大步长可能跨过边界或漏掉高强度区域；极小步长又浪费计算。PDMP 更适合 ODE event detection 和累计风险求根。

### 4. 忽略事件爆炸

必须排除有限时间内发生无限多次跳跃：

$$T_n\rightarrow\infty\quad\text{几乎必然}$$

如果一次跳跃会把系统推向更高强度，并形成正反馈，就要特别检查非爆炸条件。

### 5. 把离散事件重复计入

同一技能效果不能既在连续流中扣除全部伤害，又在跳跃时再扣一次。

### 6. 把纯 PDMP 当成万能模型

如果连续轨迹确实含有显著扩散噪声，就应升级为 jump diffusion，而不是硬把噪声塞进随机跳跃。

## 十三、如何判断一个问题适不适合 PDMP？

可以依次问四个问题：

1. 两个事件之间的状态能否由 ODE 或确定性规则较好描述？
2. 是否存在随机到达、故障、命中或重置事件？
3. 事件发生概率是否依赖当前连续状态？
4. 跳跃之后，未来是否只依赖新的完整状态？

如果四个答案基本都是“是”，PDMP 往往很合适。

典型应用包括：

- 设备可靠性和预防维修；
- 神经元放电；
- 排队与通信网络；
- 保险和信用事件；
- 分子动力学；
- Hawkes 强度状态；
- 自动驾驶和机器人混合控制；
- 游戏中的事件驱动战斗与资源系统。

---

## 结语

PDMP 最重要的思想不是“连续时间加几个随机事件”，而是把系统明确拆成三层：

$$\text{连续流}\quad+\quad\text{事件强度}\quad+\quad\text{跳后重置}$$

这种拆分让模型既能保留物理和规则结构，又能表示真正存在的不确定事件。

对 5v5 游戏而言，它提供了一种很自然的中间层：底层位置、冷却和持续效果连续演化；命中、击杀、刷新和传送通过事件处理；高层策略通过受控 PDMP、HJB 或事件时刻动态规划做决策。

它不会替代所有 MDP、SDE 或行为树，但在“事件稀疏、事件之间仍有连续动力学”的系统中，PDMP 往往是最贴近问题结构的那一个模型。
