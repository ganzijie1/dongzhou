# 孟德战棋强化学习模型坍缩治理方案

> 文档用途：飞书文档导入 / 强化学习训练复盘 / 后续训练验收  
> 当前状态：HAPPO 运行模型已应用 PopArt、共享 Critic 和固定熵；H-PPO 高层选项坍缩仍需继续治理  
> 更新日期：2026-08-08

## 1. 结论摘要

当前敌军主策略采用 HAPPO。针对训练中出现的策略坍缩和价值网络失稳，已经落地以下组合方案：

1. **PopArt 价值归一化**：消除不同关卡回报尺度差异，同时保持 Critic 原始输出连续。
2. **共享集中式 Critic**：让各兵种 Actor 使用同一份全局战场价值基线，减少局部策略互相漂移。
3. **固定熵奖励**：Actor 的熵系数固定为 `0.02`，训练全程保留探索压力，避免过早变成单一动作。
4. **异构 Actor**：君主、步兵、骑兵、射手、策士等兵种分别使用 Actor，避免共享 Actor 把所有兵种压成同一种行为。
5. **PPO 裁剪与梯度裁剪**：策略比率裁剪为 `0.2`，梯度范数限制为 `0.5`，防止单批异常样本破坏策略。
6. **HAPPO 顺序修正**：兵种更新顺序随机化，前序策略比率修正限制在 `[0.5, 2.0]`。
7. **多关卡随机课程训练**：每轮随机打乱战斗关卡，避免只记住单图、单阵型和单一路径。
8. **检查点与 CQL 回退**：每轮保存模型；HAPPO 无法加载时使用 CQL，避免运行时退回失控策略。

当前部署模型 `rl/models/runtime/happo.pt` 的检查点元数据为：

```text
value_normalization = popart
entropy_coef = 0.02
```

## 2. 什么是本项目中的“模型坍缩”

模型坍缩不是单一故障，至少包含四种表现。

| 类型 | 表现 | 主要风险 |
|---|---|---|
| 策略熵坍缩 | 几乎所有状态都选择同一种动作 | 敌军只前冲、只待机或只攻击最近目标 |
| 角色坍缩 | 不同兵种形成相同策略 | 射手不会找射界，近战不会让路，策士不会施法 |
| 价值尺度失稳 | Critic 损失剧烈变化，优势估计失真 | Actor 被错误优势推动，短时间内策略崩坏 |
| 高层选项坍缩 | H-PPO 的管理器固定选择一个战术选项 | 分层策略名义存在，实际退化为普通 PPO |

早期 H-PPO 实验中，确定性评估时四个高层选项全部选择第 4 项，这是明确的选项坍缩。当前 HAPPO 的稳定化方案不能直接证明 H-PPO 已经解决。

## 3. 根因分析

### 3.1 跨关卡回报尺度不一致

不同地图的单位数量、回合上限、伏兵、城门和胜利条件差异很大。固定尺度的 Critic 容易被高回报或长关卡主导，导致小关卡的优势信号接近噪声。

### 3.2 合法动作数量变化大

单位在开阔地、城门、营寨和射程边缘的合法动作数量完全不同。若熵奖励快速衰减，网络会过早锁定少数高频动作。

### 3.3 兵种职责天然异构

步兵、骑兵、射手、策士和君主的有效行动分布不同。完全共享 Actor 时，样本更多的近战兵会主导梯度，使少数兵种失去自己的策略。

### 3.4 多智能体同时更新造成非平稳

一个 Actor 更新后，其他 Actor 面对的环境已经变化。如果不保留更新顺序和策略比率修正，后更新角色会使用过期优势。

### 3.5 单地图训练导致伪最优

只在一张地图训练时，模型可能记住坐标、固定敌人和固定最短路，而没有学会射界、堵路、集火和撤退等可迁移策略。

## 4. 已落地的治理措施

### 4.1 PopArt 价值归一化

Critic 维护回报的滑动均值和二阶矩：

```text
mean_t = beta * mean_(t-1) + (1 - beta) * batch_mean
second_t = beta * second_(t-1) + (1 - beta) * batch_second_moment
std_t = sqrt(max(second_t - mean_t^2, epsilon))
```

当前参数：

| 参数 | 数值 |
|---|---:|
| `beta` | `0.999` |
| `epsilon` | `1e-5` |
| Critic 隐藏层 | `256 × 256` |

更新统计量时同步调整输出层权重与偏置，保证归一化前后的实际价值预测不突变。这一点比普通运行均值归一化更重要，否则统计量更新本身也会成为训练扰动。

### 4.2 共享集中式 Critic

所有兵种 Actor 共用一个观察完整战场状态的 Critic：

```text
全局战场状态 -> 共享 PopArt Critic -> V(s)
局部单位状态 + 合法候选动作 -> 对应兵种 Actor -> 动作概率
```

共享 Critic 提供统一价值尺度；独立 Actor 保留兵种差异。这是“共享价值、分离策略”，不是所有网络参数完全共享。

### 4.3 固定熵系数

Actor 损失为：

```text
actor_loss = ppo_policy_loss - 0.02 * entropy
```

熵系数固定为 `0.02`，不随训练步数衰减。原因是战场合法动作数量和关卡分布持续变化，过早衰减会让后续关卡没有重新探索的能力。

固定熵只能延缓策略变尖，不能单独解决所有坍缩问题，必须与多关卡采样、角色拆分和稳定价值基线配合。

### 4.4 独立兵种 Actor

当前 Actor 分组：

```text
Lord, King, Infantry, Cavalry, Archer, Strategist,
Support, Artillery, Fighter, Bandit, Other
```

每个角色拥有独立网络和优化器。射手的射界样本不会被步兵的大量近战样本直接覆盖，策士也可以形成独立的技能使用分布。

### 4.5 PPO 与梯度稳定器

| 机制 | 当前值 | 作用 |
|---|---:|---|
| PPO clip range | `0.2` | 限制单次策略更新幅度 |
| GAE gamma | `0.99` | 平衡长期收益 |
| GAE lambda | `0.95` | 降低优势估计方差 |
| Advantage 标准化 | 每批执行 | 防止个别关卡优势尺度主导更新 |
| Gradient norm clip | `0.5` | 抑制梯度爆炸 |
| Value loss coefficient | `0.5` | 控制 Critic 更新强度 |

### 4.6 HAPPO 顺序更新与修正

每批训练随机排列当前出现的兵种，再逐个更新 Actor。前序 Actor 更新造成的策略变化会累积为修正系数：

```text
correction = clip(correction * policy_ratio, 0.5, 2.0)
```

限制区间可以避免某个兵种的大幅更新把后续兵种的有效优势放大到不可控范围。

### 4.7 多关卡随机课程

东周关卡训练脚本会扫描战斗关卡，每轮随机打乱顺序，再按关卡组收集样本。当前 PopArt 训练记录使用：

| 参数 | 数值 |
|---|---:|
| 扫描关卡数 | `41` |
| 训练轮数 | `2` |
| 每关采样 | `128` 步 |
| 每次更新关卡数 | `1` |
| 更新 epoch | `2` |
| batch size | `8` |
| 最大单局动作数 | `160` |
| seed | `2059` |
| 总敌军训练样本 | `9984` |

这种配置牺牲一部分吞吐量，换取更频繁的跨关卡更新和小样本角色的梯度机会。

### 4.8 奖励塑形约束

敌军训练奖励在原生胜负与伤害回报上增加小幅战术信号：

- 攻击或施法给予小额正反馈。
- 实际伤害按上限截断后加入奖励。
- 有效射界、战术位置等特征给予小额奖励。
- 无意义等待和不利动作给予小额惩罚。

塑形权重保持低于终局胜负和击杀收益，避免模型只刷局部特征而不完成关卡目标。

## 5. 已有训练结果

`happo_dongzhou_popart` 报告摘要：

| 指标 | 结果 |
|---|---:|
| 训练样本 | `9984` |
| 更新次数 | `78` |
| 确定性评估敌军胜率 | `100%` |
| 平均回报 | `11.9288` |
| 训练中最低原始策略熵 | `3.1863` |
| 最后一次策略熵 | `3.2787` |
| 平均顺序修正系数最小值 | `0.7160` |
| 平均顺序修正系数最大值 | `1.7902` |
| 训练耗时 | `72.89 秒` |

策略熵没有向零快速收缩，顺序修正均保持在保护区间内，说明该轮训练没有出现明显的 HAPPO 动作分布坍缩。

注意：`curriculum_v3` 与 `popart` 使用了不同随机种子，因此胜率差异只能作为工程信号，不能作为严格的单变量 A/B 结论。后续仍需同种子、多种子重复实验。

## 6. H-PPO 选项坍缩的后续方案

H-PPO 管理器的固定熵不能单独保证多个选项形成分工。若继续训练分层策略，应增加：

1. 记录每个高层选项的使用率、条件熵和互信息。
2. 对长期低使用率选项使用平衡采样或轻量使用率奖励。
3. 为不同选项加入行为差异约束，避免多个选项输出同一低层策略。
4. 在多地图、多出生点和多阵营规模上训练，而不是单场景 4096 步实验。
5. 管理器与执行器使用不同学习率，管理器更新频率更低。
6. 设置最短选项持续时间，避免管理器逐步退化成普通动作选择器。

在这些验收项完成前，H-PPO 不应替换当前 HAPPO 运行策略。

## 7. 监控与坍缩判据

每次训练至少记录以下指标：

| 指标 | 建议告警条件 |
|---|---|
| 归一化策略熵 `H / log(N_legal)` | 连续 10 次更新低于 `0.35` |
| 单动作类型占比 | 连续评估超过 `85%` |
| 各兵种动作分布差异 | 射手、近战、策士长期接近同分布 |
| HAPPO 修正系数 | 多次贴近 `0.5` 或 `2.0` 边界 |
| Value loss | 连续增长且回报下降 |
| PopArt std | 接近零或短期剧烈跳变 |
| 确定性 / 随机策略差距 | 确定性胜率显著低于采样胜率 |
| 多地图胜率方差 | 少数地图胜率为零或显著落后 |

原始熵受合法动作数影响，不能只看绝对值。应优先使用除以 `log(N_legal)` 的归一化熵。

## 8. 推荐训练与验收流程

### 8.1 训练命令

```powershell
.\.venv-rl\Scripts\python.exe -m rl.train_happo_dongzhou `
  --executable build\rl-vcpkg\game\src\rl\Release\mengde_rl.exe `
  --output rl\models\happo_dongzhou_candidate `
  --stage-count 41 `
  --passes 2 `
  --steps-per-stage 128 `
  --stages-per-update 1 `
  --epochs 2 `
  --batch-size 8 `
  --max-episode-actions 160 `
  --seed 2059
```

### 8.2 最低验收条件

- 至少使用 3 个随机种子重复训练。
- 评估覆盖全部战斗关卡，不只评估示例地图。
- 归一化熵不触发连续告警。
- 每个实际出场兵种都有有效样本和非退化动作分布。
- 城门、栅栏、射手让路、技能、伏兵和补给点场景均进入评估集。
- 新模型胜率和平均回报不低于当前运行模型。
- 保存训练报告、检查点和失败关卡清单后，才允许覆盖运行模型。

### 8.3 部署与回退

运行时加载顺序：

```text
rl/models/runtime/happo.pt
    -> 加载失败时使用实验目录 HAPPO
    -> HAPPO 不可用时回退 CQL
    -> 两者均不可用时安全待机
```

部署前保留上一版 `happo.pt`。新模型出现动作单一化、关键关卡胜率下降或加载错误时，直接恢复上一检查点，无需修改战斗规则。

## 10. 最终判断

当前解决模型坍缩的核心不是单独调高熵，而是：

```text
PopArt 稳定价值尺度
    + 共享 Critic 统一全局基线
    + 独立 Actor 保留兵种差异
    + 固定熵维持探索
    + PPO / 梯度裁剪限制更新幅度
    + HAPPO 顺序修正控制多智能体非平稳
    + 多关卡随机训练防止单图记忆
```

该组合已经用于当前 HAPPO 运行模型。H-PPO 的高层选项坍缩需按第 6 节单独治理，暂不纳入正式运行策略。
