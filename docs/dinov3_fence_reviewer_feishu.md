# 孟德战场地形识别：DINOv3 + 高召回围栏复核器

> 文档用途：飞书文档导入 / 地形标注方案说明 / 模型验收与后续迭代  
> 当前状态：已接入候选预测流程，不允许自动写入关卡 Lua  
> 更新日期：2026-08-09

## 1. 结论摘要

当前地形识别采用两阶段方案：

1. **DINOv3 多分类器**负责平原、山地、树林、城墙、营寨、围栏等常规地形的初步分类。
2. **独立围栏复核器**只判断“这一格是否可能包含围栏”，以高召回方式补捉主分类器漏掉的细长栅栏结构。
3. 两个模型都只生成建议，任何低置信格、特殊地形和疑似围栏都必须进入人工复核。
4. 写入 Lua 后必须通过地形拓扑审计、单位落点检查和实机寻路测试。

围栏复核器将完整地图留出验证中的围栏召回率从主分类器的 `3.85%` 提升到 `80.77%`。代价是精度只有 `5.37%`，因此它适合作为“漏检报警器”，不适合直接覆写地形。

第十二关 `m008.png` 的实测结果：

|---|---:|
| 真实围栏格 | 19 |
| 进入复核候选的真实围栏 | 19 |
| 围栏候选总数 | 23 |
| 南侧营门 `(9,10)` 是否误报 | 否 |
| 是否允许自动写入 | 否 |

## 2. 问题背景

曹操传风格地图中的营寨通常同时包含三种语义：

- 营寨内部：可通行、可补给。
- 木制围栏：不可通行。
- 营门：可通行，必须连接营内和营外。

早期标注把营寨的整个外接矩形统一写成 `Camp`，结果视觉上的木栅栏也可以穿越。第一次修正时又把南侧营寨顶部中央营门写成 `Fence`，造成我军完全无法离开营寨。

这说明仅判断“这一块看起来像营寨”不够，还必须识别营寨内部结构，并验证围栏是否连续、入口是否存在。

## 3. 为什么单一多分类器不够

当前训练集包含 `44` 张有效地图、`12204` 个网格样本，但围栏只有 `82` 格，而且只来自 `4` 张地图。

| 数据项 | 数量 |
|---|---:|
| 有效地图 | 44 |
| 总网格样本 | 12204 |
| 围栏样本 | 82 |
| 含围栏地图 | 4 |
| 围栏样本占比 | 约 0.67% |

围栏同时具备以下难点：

- 类别极度不平衡。
- 围栏是细长结构，占单格像素比例很低。
- 不同 MOD 的木栅栏颜色、宽度和方向差异较大。
- Lua 关卡地形来自历史人工配置，本身属于弱监督，可能存在错标。
- 单格营帐和大型围栏营寨都使用 `Camp` 语义，外观尺度不一致。

在这种情况下，多分类器更容易把围栏判成树林、草地、山地或营寨。

## 4. 总体架构

```text
战场位图
    |
    v
按逻辑地图网格切分（例如 19 x 14）
    |
    +--> DINOv3 方向感知特征 --> 多分类 LogisticRegression
    |                              |
    |                              +--> 普通地形建议 + 分类置信度
    |
    +--> 同一组方向感知特征 --> 围栏二分类 LinearSVC
                                   |
                                   +--> 疑似围栏格 + fence_score

两路结果合并
    |
    +--> 低置信格复核
    +--> 疑似围栏复核
    +--> 城墙 / 围栏 / 营门 / 补给点强制复核
    |
    v
人工确认后的 Lua 地形矩阵
    |
    +--> 拓扑审计
    +--> 单位落点检查
    +--> movement_range / movement_path 实机测试
```

## 5. DINOv3 地形分类器

### 5.1 视觉骨干

当前使用本地 ModelScope 权重：

```text
output/model_cache/modelscope/dinov3-vits16-pretrain-lvd1689m
```

地图先缩放到每个逻辑格对应 `2 x 2` 个 DINO patch token，再提取稠密视觉特征。

### 5.2 方向感知池化

旧版只保留每格 token 的均值和最大值，会把细长围栏与背景混合。新版增加两个方向差分：

```text
mean_tokens       = 单格 2 x 2 token 均值
max_tokens        = 单格 2 x 2 token 最大值
horizontal_delta  = 右半格特征 - 左半格特征
vertical_delta    = 下半格特征 - 上半格特征
```

最终特征由以下部分拼接：

```text
DINO mean
+ DINO max
+ horizontal delta
+ vertical delta
+ RGB / HSV / 灰度分位数 / 梯度等手工特征
= 1749 维
```

方向差分对横向栅栏、纵向栅栏、城墙边缘和营门断口更敏感。

### 5.3 多分类头

主分类器采用带类别平衡的 Logistic Regression：

| 参数 | 当前值 |
|---|---:|
| `class_weight` | `balanced` |
| `C` | `0.03` |
| `max_iter` | `1000` |
| `solver` | `lbfgs` |
| 随机种子 | `20260809` |

主分类器负责输出完整地形矩阵和每格置信度，不负责最终批准。

## 6. 独立高召回围栏复核器

### 6.1 设计目的

围栏复核器不是第二个完整地形分类器，只处理一个二分类问题：

```text
Fence vs. Not Fence
```

其目标函数偏向召回率：宁可多报一些疑似围栏，也要尽量避免把真实围栏漏成可通行地形。

### 6.2 当前实现

| 参数 | 当前值 |
|---|---:|
| 模型 | `LinearSVC` |
| `class_weight` | `balanced` |
| `C` | `0.03` |
| `dual` | `auto` |
| `max_iter` | `5000` |
| 目标召回 | 至少 `0.80` |
| 当前阈值 | `-0.672728` |

阈值在整张地图分组留出集上选择：在召回率不低于 `80%` 的候选阈值中，选择精度最高的一个。

### 6.3 输出格式

预测 JSON 除常规的 `review_required` 外，新增：

```json
{
  "fence_review_required": [
    {
      "x": 15,
      "y": 6,
      "current_prediction": "P",
      "fence_score": 0.8421
    }
  ]
}
```

该列表只表示“必须检查”，不表示可以直接改为 `Fence`。

## 7. 验证方法与当前指标

### 7.1 数据划分

验证使用 `GroupShuffleSplit`，按完整地图资源分组，而不是随机拆散单格。

这样可以避免同一张地图的相邻格同时出现在训练集和验证集，造成虚高指标。

### 7.2 主分类器指标

| 指标 | 当前结果 |
|---|---:|
| 总体准确率 | `45.40%` |
| Macro F1 | `27.45%` |
| 主分类器围栏召回率 | `3.85%` |
| `auto_apply_eligible` | `false` |

这些指标说明当前弱监督数据不足以支撑自动地形写入。

### 7.3 围栏复核器指标

| 指标 | 当前结果 |
|---|---:|
| 围栏召回率 | `80.77%` |
| 围栏精度 | `5.37%` |
| 围栏 F1 | `10.07%` |
| 验证集真实围栏 | 26 |
| 复核候选 | 391 |

`80.77%` 是围栏候选召回率，不是整体地形准确率。低精度意味着候选中包含大量误报，所以仍需人工和拓扑规则过滤。

## 8. 第十二关案例

地图：`assets/lzc/map/m008.png`  
关卡：`game/sce/dongzhou/stage/08.lua`

南侧营寨修正后的关键结构：

```text
北侧
P P e P P    <- 中央 e 为营门 (9,10)
P e e e P
P e e e P
P P e P P    <- 南侧中央入口
南侧
```

其中：

- `P`：不可通行围栏。
- `e`：可通行营寨地形。
- 顶部中央 `(9,10)` 必须连接营外 `(9,9)` 与营内 `(9,11)`。
- 营门北侧 (9..11,7..9) 是开阔通道，不得误标为山地。

实机验证路径：

```text
(9,12) -> (9,11) -> (9,10) -> (9,9)
```

正式模型在该地图上生成 `23` 个围栏候选，其中包含全部 `19` 个真实围栏，并且没有把 `(9,10)` 营门列为围栏候选。

## 9. 安全约束

当前流程禁止模型直接覆写 Lua，原因如下：

1. 主分类器总体指标仍低。
2. 围栏复核器精度低，只适合查漏。
3. 营门和围栏外观接近，误封入口会导致单位无法行动。
4. 历史 Lua 标签是弱监督，训练数据可能继承旧错误。

任何地图至少满足以下验收条件：

- 所有视觉围栏标为不可通行 `Fence`。
- 围栏边界连续，不存在无意缺口。
- 每个封闭营寨至少有一个明确可通行入口。
- 营内单位存在到营外的实际寻路路径。
- 单位出生点不落在 `Fence`、`Wall`、`Water` 或 `RockyMountain`。
- `Gate`、`DeerFort`、`Castle` 与补给点配置一致。
- 专项关卡测试和全局障碍测试全部通过。

## 11. 后续改进路线

### 11.1 扩充人工复核数据

当前只有 `4` 张地图含围栏标签。下一阶段应至少人工复核 `10~20` 张包含营寨、城墙和栅栏的地图，并将以下类别分开标注：

- 水平围栏。
- 垂直围栏。
- 围栏转角。
- 营门开口。
- 营寨内部。
- 围栏附近的树林、岩石和帐篷硬负样本。

### 11.2 建立专用围栏验证集

不能继续只依赖一次随机整图切分。应建立固定的地图级验证集，并报告：

- Leave-One-Map-Out 围栏召回率。
- 每张地图的围栏召回率和误报数。
- 营门误封率。
- 完全封死营寨的拓扑失败次数。

### 11.3 使用分割模型处理细结构

当人工 mask 数量足够后，可将围栏识别升级为 SegFormer MiT-B2/B4 或其他细粒度语义分割模型。分割模型在像素级预测围栏，再通过网格投票转换成 Lua 地形。

在数据不足阶段，直接换更大的视觉骨干不会自动解决标签稀缺和错标问题。

### 11.4 增加拓扑后处理

模型候选进入以下结构化检查：

```text
识别连续围栏组件
    -> 查找组件包围的营寨格
    -> 检查是否存在入口
    -> 检查营内到营外的连通路径
    -> 若完全封闭，则强制进入人工复核
```

拓扑检查只负责发现矛盾，不应凭空决定哪一格是营门。

## 13. 最终判断

当前方案不是“模型自动标地图”，而是：

```text
DINOv3 提供完整地形建议
    + 独立围栏复核器高召回查漏
    + 人工确认特殊地形
    + 拓扑审计防止营寨被封死
    + 实机寻路测试验证实际行为
```

这一组合已经解决第十二关围栏可穿越和营门被封死的问题，但要进一步降低人工成本，关键不是继续无条件增大模型，而是增加跨地图、像素级、经过人工确认的围栏与营门标注。
