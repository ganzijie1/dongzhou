# CQL 防坍缩优化与 HAPPO 对比实验

> 场景：`example` 固定离线数据集  
> 数据：48 局、1357 条 transition  
> 评估：10 局，统一种子 `12026-12035`  
> 日期：2026-08-08

## 1. 实验结论

纯离线 CQL 的主要坍缩风险来自 Critic 价值外推，不是在线 PPO 式策略熵坍缩。因此最终方案调整为：

- Critic 侧 CQL-Lagrange 自适应 `alpha`。
- 显式监控 `Q_ood_mean - Q_data_mean`。
- 奖励按 1%/99% 分位裁剪。
- Actor 只保留 max-Q 和 `0.05` 轻量 BC，不使用固定熵损失。
- 离散推理直接使用 `argmax(min(Q1, Q2))`。
- 旧 CQL 双 Q 作为初始化，避免短预算从零训练不收敛。

最终候选保持 100% 胜率，`alpha=1.04`，`Q_ood-Q_data=-0.46`，Q 标准差 `4.10`，没有出现过保守导致的 Q 平原。

但其平均回报 `22.4941` 低于旧 CQL 的 `22.7970`，因此当前不替换运行时 CQL。

## 2. 最终同基准结果

| 策略 | 胜率 | 平均回报 | 回报标准差 | 平均动作数 | 最大动作类型占比 |
|---|---:|---:|---:|---:|---:|
| 旧 CQL | 100% | 22.7970 | 0.9334 | 12.6 | 50.79% |
| CriticAdaptiveCQL | 100% | 22.4941 | 0.7532 | 14.0 | 52.14% |
| HAPPO | 90% | 23.0868 | 4.8676 | 22.6 | 46.46% |

解释：

- HAPPO 平均回报最高、动作类型最分散，但胜率和稳定性低于两种 CQL。
- 旧 CQL 仍是当前最好的实时故障回退：胜率 100%，动作最少，平均回报略高。
- CriticAdaptiveCQL 降低了回报方差，但没有超过旧 CQL 的平均回报和动作效率。

## 3. Critic 健康诊断

| 指标 | 最终值 | 判断 |
|---|---:|---|
| `Q_data_mean` | 9.9000 | 数据动作价值正常 |
| `Q_ood_mean` | 9.4397 | 低于数据动作 |
| `Q_ood-Q_data` | -0.4603 | 接近目标 -0.5 |
| 自适应 `alpha` | 1.0415 | 未贴近 0.05 或 5.0 边界 |
| `Q_data_std` | 4.1009 | Q 未被压成平原 |
| Bellman loss | 2.8971 | 仍有继续训练空间 |
| 奖励裁剪 | [-2.0808, 12.3051] | 排除两端 1% 异常尺度 |

诊断判据：

```text
过保守：Q_ood-Q_data 长期远低于目标，alpha 下降到下界，Q 方差接近 0
保守不足：Q_ood-Q_data 高于目标，alpha 持续上升到上界
健康：Q(data) 稳定高于 Q(OOD)，alpha 不贴边，Q 保持有效方差
```

## 4. 失败实验与原因

### 4.1 固定熵 AdaptiveCQL

首版给离线 Actor 加自适应温度和熵目标，600 次更新后：

| 指标 | 结果 |
|---|---:|
| 胜率 | 60% |
| 平均回报 | 18.4435 |
| 平均动作数 | 75.7 |
| 待机占比 | 77.7% |

虽然训练归一化熵为 `0.6465`，但确定性 `argmax` 仍由待机占据。结论是：高分布熵不能解决 Critic 外推，也不能保证最高概率动作不坍缩。

### 4.2 Critic 从零训练 600 步

去掉固定熵后，从零训练 Critic：

- `alpha=1.17`，没有过大。
- `Q_ood-Q_data=-0.32`，反而保守不足。
- `Q_data_std=0.87`，没有完全压平。
- max-Q 评估仅 50% 胜率。

主要问题是 600 步预算不足以从零重建旧 CQL 已训练 1500 步的价值函数。因此最终使用旧 Q 初始化后再做自适应 alpha 微调。

### 4.3 OOD 目标 -1.0

旧 Q 初始化、目标 `-1.0` 的 300 步微调结果：

| 指标 | 结果 |
|---|---:|
| 胜率 | 100% |
| 平均回报 | 22.5524 |
| 回报标准差 | 0.6407 |
| 平均动作数 | 12.3 |
| `Q_ood-Q_data` | -0.4728 |
| `alpha` | 1.0783 |

该版本动作效率最好，但 `alpha` 仍在向上调整，目标对离散动作偏严。报告已单独保留，未设为默认。

## 5. 工程实现

最终 `CriticAdaptiveCQL` 包含：

1. 双 Q 与目标网络。
2. 旧 CQL 检查点初始化。
3. 分位奖励裁剪和可选奖励缩放。
4. 自适应 `alpha`，范围 `[0.05, 5.0]`。
5. 默认 OOD/Data 目标差 `-0.5`。
6. `Q_data_mean`、`Q_ood_mean`、Q 方差和 alpha 监控。
7. `0.05` 轻量 BC，仅辅助 Actor；离散运行策略使用 max-Q。
8. 梯度裁剪和目标网络软更新。

## 6. 部署判断

当前运行时继续使用旧 CQL，不复制实验模型到 `rl/models/runtime/cql.pt`。

原因：

- 新模型没有提高胜率，二者均为 100%。
- 新模型平均回报低约 1.33%。
- 新模型平均动作数多 1.4。
- 新模型的优势主要是回报方差降低，不足以抵消效率下降。

后续只有在东周多关卡数据、至少 3 个随机种子下稳定超过旧 CQL，才应替换运行时模型。
