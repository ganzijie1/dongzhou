# 攻城联合规划运行时

本文记录曹操传式方格战棋的运行时联合规划实现。设计参考两份飞书文档：攻城战术需求，以及 MAPF 方法综述与工程选型。目标不是替代原生规则，而是在原生合法动作集合上协调单位顺序、位置和火力通道。

## 1. 决策分层

```text
原生引擎：生成所有待行动单位的合法动作
    -> HAPPO / CQL：提供动作软偏好
    -> 战术场：计算威胁、城门距离、射界和通道阻塞
    -> 槽位分配：伤兵撤退位、弓弩火力位、投石车位
    -> 时间展开预留：检查节点冲突和反向边冲突
    -> 执行一个动作
    -> 读取新状态并滚动重规划
```

学习模型不能绕过原生合法动作，也不负责证明路径可行。模型缺失时，规则规划器仍正常工作。

## 2. 时空预留

单位路径写作

$$
P_i = (v_i^0, v_i^1, \ldots, v_i^T), \qquad T \le H.
$$

当前窗口长度为 `H = 12`。预留表记录两类资源：

$$
R_V(t, v) = i,
$$

表示单位 `i` 在时刻 `t` 占据格子 `v`；以及

$$
R_E(t, u, v) = i,
$$

表示单位 `i` 在时刻 `t` 从 `u` 移动到 `v`。候选路径在以下任一条件成立时被拒绝：

$$
R_V(t, v_i^t) = j, \quad j \ne i,
$$

或

$$
R_E(t, v_i^t, v_i^{t-1}) = j, \quad j \ne i.
$$

第二个条件专门阻止两个单位沿同一条边对穿换位。单位到达终点后，终点保持预留到窗口结束。

## 3. 战术约束

- 重伤单位：生命比例不高于 `0.35` 时，提高降低威胁或拉开敌距的移动优先级，并压低攻击、等待和继续顶线的动作。
- 远程与投石车：依据可攻击敌人数生成火力槽位，投石车攻击另有优先级奖励。
- 城门前排：射程 1、无法产生火力且贴近城门的单位优先后撤，让出前沿格。
- 射界通道：检测阻挡远程单位最短射击路径的友军；阻挡者离开通道得到奖励，其他近战进入通道受到硬惩罚。
- 槽位分配：使用最大权二分匹配，避免多个单位争用同一战术位置，并检查兵种角色约束。

## 4. 动态优先级与局部重规划

单位的基础动作分数由战术收益与模型先验组成：

$$
S(i, a) = S_{tactic}(i, a) + w_p S_{model}(i, a) + w_w A_i.
$$

`A_i` 是等待年龄。一次决策未选中的待行动单位年龄加一，被选中单位清零，且设置上限，避免低优先级单位长期饥饿。高优先级路径产生冲突时，规划器在该单位的候选动作中继续尝试；每个原生动作执行后再对新局面整体规划，因此不维护容易失效的长动作脚本。

## 6. 明确限制

当前方案是窗口化优先级 MAPF，不是 CBS、EECBS 或全局最优联合搜索。它适合单位数量较多、每次动作后世界状态会变化的实时游戏运行时。若后续基准出现大量窄门死锁，再按冲突群局部切换 PIBT 或 EECBS；在此之前，不为理论最优性承担不必要的帧耗时。
