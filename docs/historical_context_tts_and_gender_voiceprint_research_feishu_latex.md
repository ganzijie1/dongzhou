# 史实上下文驱动角色语音合成与男女声纹验收

> 论文、开源项目与《东周列国志》游戏落地方案（飞书 LaTeX 版）
> 调研日期：2026-11-03
> 适用范围：角色台词合成、历史人物配音、性别与年龄段验收、说话人一致性、剧情上下文表达

## 摘要

当前配音的核心短板不是“声音文件不够多”，而是**角色身份、史实上下文和表达方式没有进入合成条件**。现有版本已经覆盖 2,315 句非旁白台词、688 个说话人，并修正了已知男女声映射错误，但底层仍主要依赖少量公开预设音色逐句合成。同一音色被大量人物复用，每句又被当作孤立文本处理，因此即使性别正确，也会出现“所有老臣像同一个人”“君王、将军、史官只有音高差别”“台词像朗读而不是表演”等问题。

调研结论是：应把配音重构为“**史实上下文编译器 + 可控语音生成器 + 多模型验收门**”。生成侧优先采用支持中文、零样本音色和自然语言指令控制的 CosyVoice 系列；身份侧使用 WeSpeaker 或 SpeechBrain ECAPA-TDNN 做说话人嵌入；男女与年龄段使用独立属性分类器；情绪侧可用 SenseVoice 做粗粒度复核；文本正确性用 ASR/CER；最终仍保留分层人工试听。不能把男女识别、声纹识别和情绪识别混成一个模型，也不能把“男声降调”当成角色塑造。

## 1. 当前问题诊断

### 1.1 公开预设音色不等于角色声音

当前 Edge TTS 方案生成的是合成音频，并非直接复制某段公开录音；但它使用的是公开预设说话人，玩家听到的仍是高度熟悉、可复用的音色模板。688 个角色共享少量基础音色时，人物之间缺少稳定而可辨识的身份边界。

需要同时满足两个目标：

1. 同一角色跨章节、跨情绪仍能被听出是同一个人。
2. 不同角色即使同为男性老臣，也应在音色、节奏、气息、句尾和权力姿态上可区分。

这两个目标不能只靠音高完成。声纹包含声道特征、频谱包络、发声习惯和时序模式；情绪与表演则更多体现在基频轨迹、能量、时长、停连和重音。

### 1.2 当前逐句合成丢失剧情关系

周宣王对臣下下令、杜伯被诬后自辩、将领临阵催军，即使文字相近，表达也不应相同。决定声音的上下文至少包括：

- 角色：性别、年龄段、身份、官职、身体状态、长期性格。
- 关系：君臣、父子、盟友、敌手、上下级、公开场合或私下谈话。
- 场景：朝堂、军阵、营帐、败退、密谋、祭祀、审判、临终。
- 行为：宣告、质问、规劝、辩解、诱敌、安抚、威慑、哀悼。
- 前文：上一说话人、上一句的情绪、冲突是否升级、信息是否首次揭露。
- 史实：人物当时所处年代、政治位置和事件阶段；年龄无法可靠确定时只能使用“青年/壮年/中老年”等区间，不得编造精确年龄。

### 1.3 性别正确仍可能没有特色

性别是硬约束，角色特色是多维软控制。周宣王应首先通过“成年男性”硬门，但“君王”不等于持续低沉咆哮；杜伯是老臣，也不等于每句沙哑迟缓。历史角色需要克制、礼制和关系变化，避免脸谱化。

## 2. 论文脉络

### 2.1 从情绪标签转向上下文条件

《Contextual Expressive Text-to-Speech》提出 Contextual TTS：不再只输入“高兴/悲伤”等固定标签，而是让文本上下文本身指导表达。这与历史剧情非常契合，因为“被君王质疑的老臣”比单一“愤怒”标签包含更多可表演信息。

《M2-CTTS》进一步使用历史对话中的文本与声学信息，并同时建模全局和局部尺度。对东周项目的直接启示是：当前句不能只看前文文本，还应读取上一句实际音频的语速、能量和基频趋势，避免连续对话每句都从中性状态重新开始。

《CLAPSpeech》使用文本—音频对比学习，把上下文与高层韵律对齐，并进行多尺度预训练。它说明“上下文是否真的改变韵律”可以被建模和评价，而不是只靠主观提示词。

《DailyTalk》提供带对话历史的会话语音数据与基线；《DNASpeech》则把 Dialogues、Narratives、Actions 同时作为 situated prompt。东周的剧情数据天然包含对话、叙事和行动，适合沿用 DNA 结构构造自己的中文历史角色数据，而不是把整段史书直接塞给 TTS。

### 2.2 自然语言风格指令与可控生成

《InstructTTS》用自然语言风格提示控制表达，并尝试解耦风格、说话人和文本内容。工程上应把“角色是谁”和“此句怎么说”分开：角色参考音频约束身份，结构化提示约束场景、态度和韵律。

CosyVoice 2 将语言模型与流匹配用于多语种、低延迟语音合成，官方项目提供零样本、跨语种和指令模式。CosyVoice 官方代码为 Apache-2.0，但模型权重仍需逐一检查对应模型卡。它对中文和指令控制的支持使其比固定 Edge 音色更适合作为东周主生成器。

StyleTTS 2 用风格扩散和语音语言模型判别器提升自然度和零样本适配能力，适合作为风格扩散的研究基线。不过其中文能力、模型权重条款和角色参考音频授权需要单独评估，不建议直接替换为唯一生产方案。

### 2.3 声纹、性别与说话人分离

ECAPA-TDNN 通过 Res2Net、通道注意力、多层特征聚合和注意力统计池化提取说话人嵌入，是成熟的说话人验证基线。WeSpeaker 提供面向研究和生产的嵌入、相似度与说话人验证工具，代码为 Apache-2.0；SpeechBrain 也提供 ECAPA-TDNN 实现和 VoxCeleb 预训练方案。

pyannote.audio 主要解决“谁在何时说话”的分段与聚类，适合清理多人参考录音或长录音，不是男女分类器，也不是单句 TTS 的必要组件。

audEERING 的 wav2vec2 年龄—性别模型可输出 child、female、male 概率和年龄估计，适合快速建立离线审计基线，但其模型卡标注 CC-BY-NC-SA-4.0，商业产品不能未经许可直接作为生产依赖。可将其用于研究验证，再用授权明确的数据训练项目自有分类器。

## 3. 数学定义与验收公式

### 3.1 史实上下文表示

设第 $t$ 句文本为 $x_t$，最近 $k$ 轮对话为 $H_t$，角色史实卡为 $r_s$，当前场景与行为为 $q_t$，上一轮声学统计为 $a_{t-1}$。上下文向量定义为：

$$
c_t = E(H_t, r_s, q_t, a_{t-1}, x_t)
$$

生成器接收目标文本、角色音色参考和风格上下文：

$$
\hat{y}_t = G(x_t, v_s, c_t)
$$

其中 $v_s$ 只负责“像谁”，$c_t$ 负责“此时怎么说”。二者不能混用，否则情绪改变会破坏角色身份，或者所有台词只剩同一种表演。

### 3.2 说话人一致性

用说话人编码器 $f_{spk}$ 提取参考音频 $y_s^{ref}$ 与生成音频 $\hat{y}_t$ 的嵌入：

$$
e_s = f_{spk}(y_s^{ref}), \qquad \hat{e}_t = f_{spk}(\hat{y}_t)
$$

余弦相似度为：

$$
S_{spk} = \frac{e_s^{\mathsf{T}} \hat{e}_t}{\lVert e_s \rVert_2 \lVert \hat{e}_t \rVert_2}
$$

阈值 $\tau_{spk}$ 必须在项目自己的参考音色上校准，不能照搬公开测试集阈值。应同时观察同角色聚合和异角色分离：

$$
D_{within} = \frac{1}{N}\sum_i \left(1-\cos(\hat{e}_i, \bar{e}_{s(i)})\right)
$$

$$
D_{between} = \frac{1}{M}\sum_{p \ne q} \left(1-\cos(\bar{e}_p, \bar{e}_q)\right)
$$

目标是降低 $D_{within}$、提高 $D_{between}$。角色表演变化应主要体现在韵律空间，而不是让声纹嵌入大幅漂移。

### 3.3 男女与年龄段硬门

性别属性分类器输出：

$$
p_g = \operatorname{softmax}(f_g(\hat{y}_t))
$$

若角色卡要求成年男性，则基本验收条件为：

$$
p_g(\mathrm{male}) \ge \tau_g
$$

年龄段也使用概率区间，不把模型回归值当成真实历史年龄。对于无法确定年龄的史实人物，只校验青年、壮年、中老年等宽区间。基频 $F_0$ 只能作为辅助特征，不能单独决定性别或年龄。

### 3.4 综合自动验收

单句自动损失可写为：

$$
L = \lambda_{txt} L_{CER} + \lambda_{spk}(1-S_{spk}) + \lambda_g L_{gender} + \lambda_e L_{emotion} + \lambda_p L_{prosody}
$$

其中：

- $L_{CER}$：ASR 转写与原台词的字错误率。
- $1-S_{spk}$：角色身份漂移。
- $L_{gender}$：与角色卡性别不一致的惩罚。
- $L_{emotion}$：生成结果与目标情绪/言语行为的偏差。
- $L_{prosody}$：语速、停顿、重音、能量和基频轨迹偏差。

自动分数只能筛除明显错误，不能替代人工判断“是否像周宣王在此情境下说话”。最终应采用分层抽检与关键角色全检。

## 5. 东周角色语音生产方案

### 5.1 角色史实卡

每个主要角色建立结构化语音卡，不再只记录 `male/female + voiceName`：

```json
{
  "speaker": "周宣王",
  "sex": "male",
  "ageBandByScene": "adult_or_middle_aged",
  "status": "周天子",
  "voiceIdentity": "zhou_xuanwang_v1",
  "baseline": {
    "pace": "measured",
    "pitch": "mid_low",
    "energy": "controlled",
    "articulation": "clear"
  },
  "relationshipRules": [
    "朝堂宣告时克制而有权威",
    "被触怒时先收紧语速和句尾，不直接咆哮",
    "败局或疑惧场景允许短停顿和气息不稳"
  ],
  "forbiddenStereotypes": [
    "持续怒吼",
    "过度低沉",
    "现代播音腔",
    "用女声或少年声"
  ]
}
```

杜伯等老臣应采用“中老年男性 + 礼制克制 + 道德确信”的基线，但在直谏、受诬、临刑等场景分别改变停顿、力度和情绪强度。不能让“老臣”统一等于沙哑、缓慢、虚弱。

### 5.2 史实上下文编译器

每句合成前，把史书摘录、剧情事件、前后台词和人物关系压缩成短而明确的风格指令。推荐中间格式：

```json
{
  "scene": "朝堂公开质询",
  "speakerGoal": "维护天子权威并逼迫臣下表态",
  "relationship": "君对臣",
  "speechAct": "质问",
  "emotion": {"valence": -0.35, "arousal": 0.52, "dominance": 0.86},
  "delivery": {
    "pace": 0.92,
    "energy": 0.68,
    "pauseBeforeKeyword": true,
    "ending": "firm"
  },
  "doNot": ["咆哮", "戏曲腔", "现代新闻播报"]
}
```

生成给模型的自然语言指令应短、可验证，避免把整段史料原文输入模型。史料负责确定人物处境，剧情台词负责内容，语音指令只描述可听见的表达。

### 5.3 合成与候选排序

每句至少生成 3 个随机种子候选。先用硬门过滤，再综合排序：

1. ASR/CER：台词是否说对。
2. 性别与年龄段：是否违反角色卡。
3. 声纹相似度：是否保持角色身份。
4. 情绪与言语行为：是否符合当前场景。
5. 韵律连续性：是否接得住上一句。
6. 多样性：是否与同角色其他台词完全同模版。

不要对失败音频直接做大幅变调。大幅移调会改变共振峰关系并产生伪声感，也可能破坏声纹一致性。后期只用于小范围响度、静音、去噪和极轻微节奏修整；角色身份和主要情绪应在生成模型内部完成。

### 5.4 人工试听协议

关键角色每句全检，普通角色按章节分层抽检。试听人员不看模型名称，成对比较以下问题：

- 这是同一个角色吗？
- 性别和年龄段是否明显错误？
- 在不知道提示词时，能否听出宣告、规劝、质问、悲悼等言语行为？
- 与前一句连播时是否自然？
- 是否出现现代播音腔、短视频配音腔、脸谱化帝王腔或统一老臣腔？
- 是否有错读、人名地名错误、吞字、机械停顿和音量跳变？

## 6. 推荐实验设计

### 6.1 三组消融

- A 组：当前 Edge TTS 预设音色，作为基线。
- B 组：CosyVoice + 固定角色参考音色，不输入剧情上下文。
- C 组：CosyVoice + 角色参考音色 + 史实上下文编译器 + 自动验收与候选排序。

先选择 20 个高频角色、200 句台词，覆盖君王、老臣、青年将领、女性角色、平民和敌对阵营；每个角色至少包含中性、冲突、低落和高唤醒场景。不能只挑最容易合成的句子。

### 6.2 评价指标

| 维度 | 自动指标 | 人工指标 |
|---|---|---|
| 文本正确 | CER、专名错误率 | 错读与可懂度 |
| 角色身份 | WeSpeaker/ECAPA 相似度、类间距 | 同角色一致性、异角色可区分性 |
| 性别年龄 | male/female/child 概率、年龄段偏差 | 感知性别与年龄段 |
| 上下文 | 情绪/行为分类、韵律连续性 | ContextMOS、前后句连贯性 |
| 自然度 | 时长、停顿、能量异常率 | MOS、机械感 |
| 非脸谱化 | 同类角色的声纹和韵律分布 | 是否一听就是模板化帝王/老臣 |

成功标准不应只写“性别分类通过率 100%”。至少要求 C 组在上下文合适度、角色辨识度和整体偏好上显著优于 A、B 两组，同时 CER 不恶化。

## 7. 实施优先级

### P0：先建立可验收的角色身份

1. 为 20 个核心角色制作有授权的独立参考音色，禁止未经许可克隆真人。
2. 使用 WeSpeaker 建立角色声纹中心与阈值校准集。
3. 将性别/年龄分类作为独立硬门，修复后必须重新生成，不允许只改清单标签。
4. 接入 ASR 专名词表，重点覆盖人名、国名、地名和古代官职。

### P1：加入史实与剧情上下文

1. 从人物卡、关系图、章节事件和最近 3 至 5 轮台词生成结构化上下文。
2. 给言语行为、情绪强度、支配度、语速、停顿和重音建立有限且可审计的词表。
3. 生成 3 个候选，自动排序后再人工确认。
4. 连续播放整场戏验收，不能只听孤立句。

### P2：扩大覆盖并训练项目自有模型

1. 将人工选择结果保存为偏好对，训练候选排序器。
2. 收集合法授权的中文历史剧式语音数据，训练项目自有性别/年龄段分类器。
3. 对高频角色做轻量微调或适配器训练，普通角色继续零样本生成。
4. 用每章失败类型反向更新角色卡和上下文编译规则。

## 8. 风险与边界

- **史实不等于可还原真实声音**：先秦人物没有可用录音，目标只能是史实一致的艺术设计，不能宣称“复原原声”。
- **性别识别不是绝对真值**：分类器会受音高、口音、年龄、情绪和数据偏差影响；它是质量门，不是对现实人物身份的裁决工具。
- **声纹相似不代表表演正确**：同一个人可以用完全不合场景的方式说话，因此必须另做上下文与韵律评价。
- **模型许可与音色授权分开审查**：代码开源不等于权重、训练数据和参考音色都可商用。
- **避免脸谱化**：帝王不总是低沉威严，女性不总是高音柔弱，老人不总是沙哑迟缓，反派不总是阴冷耳语。
- **防止评价器过拟合**：至少使用两套独立说话人模型，并保留盲听；不能为通过单一分类器而生成失真的音频。

## 9. 结论

东周配音下一步不应继续批量替换公开预设音色，而应先完成 20 个核心角色的垂直切片。推荐生产链为：

**史实与剧情数据 → 角色卡与关系上下文 → 风格指令 → CosyVoice 多候选生成 → ASR、男女/年龄、声纹、情绪与韵律验收 → 盲听选择 → 回写偏好数据。**

该方案既能解决周宣王等人物的男女声错误，也能解决“所有男声都像同一个公开音色”的更深层问题。男女声门只是底线；真正的目标是让玩家不看名字，也能从身份、关系和场景变化中听出“是谁、对谁、为何、在什么局势下说这句话”。
